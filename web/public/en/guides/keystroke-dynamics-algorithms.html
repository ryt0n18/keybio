Keystroke dynamics algorithms: from Manhattan distance to neural networks

By Álvaro Ruiz · updated 8 November 2026 · 5 min read

A keystroke dynamics system has to answer one question: is this typing close enough to this person’s? This guide walks through how that question is answered, from classic distances to neural networks, and how to tell whether an algorithm actually works.

  2. Fixed text: distances
  3. Free text: the R and A measures

From keystrokes to numbers

The starting point is a list of events: for each key, the moment it is pressed and the moment it is released. From these come the hold times (dwell), the latencies between keys (DD and UD) and the duration of each letter combination (digraphs and trigraphs).

If everybody types the same text (a password, say), each sample becomes a vector of numbers that always has the same length: the hold time of the first key, the latency between the first and second, and so on. If the text is free, there are no fixed positions to compare, so the comparison uses the key combinations that appear in both samples.

Fixed text: distances

The simplest way to compare is to measure the distance between the new sample x and the profile mean μ:

  • Euclidean: the straight‑line distance, √Σ(xᵢ − μᵢ)². It punishes large differences heavily.
  • Manhattan: the sum of the differences, Σ|xᵢ − μᵢ|. More robust to a single, unusually slow key.
  • Scaled Manhattan: Σ|xᵢ − μᵢ| / aᵢ, where aᵢ is the mean absolute deviation of that feature in the profile. Each difference is divided by how much that person usually varies on that key, so an erratic key counts for less.
  • Mahalanobis: also accounts for how features relate to each other, but needs many samples to estimate well.

In Carnegie Mellon University’s benchmark (Killourhy and Maxion, 2009), 51 people typed the password .tie5Roanl 400 times over eight sessions. Of the fourteen detectors tested, the best was scaled Manhattan, with an equal error rate of 9.6%: a one‑line method beat far more complex ones.

Free text: the R and A measures

For free text, the classic work is by Daniele Gunetti and Claudia Picardi (Keystroke analysis of free text, 2005). They compare two samples using only the digraphs and trigraphs they share, with two measures:

The R measure: relative order

The shared combinations are sorted from fastest to slowest in each sample, and the measure captures how different those orderings are. For example:

PositionSample ASample B
1 (fastest)thhe
2heth
3iner
4 (slowest)erin

Each combination has moved one place, so the disorder is 1 + 1 + 1 + 1 = 4. The maximum possible disorder with 4 items is 8, so R = 4 / 8 = 0.5. The nice thing about R is that absolute speed does not affect it: if you type a little slower one day, the order stays the same.

The A measure: durations

A complements R by looking at the timings: it is the share of common combinations whose durations differ by more than a given margin (25% in the original paper). The lower it is, the more alike the two samples are.

Both measures are computed for digraphs, trigraphs and, optionally, individual key timings, and combined into a single distance. With texts of a few hundred characters, this approach reached very low error rates.

The threshold: when to say yes

A distance is useless without a threshold. There are two strategies:

  • Global threshold: the same for everyone. Simple, but some people are far more consistent than others.
  • Per‑user threshold: based on how similar each person is to themselves. A common technique is leave‑one‑out validation: each enrolment sample is set aside and compared with the rest, giving the mean m and standard deviation s of those distances. A sample is accepted if distance ≤ m + K·s, where K sets how strict the system is.

Moving the threshold changes both errors at once: false acceptances (FAR) and false rejections (FRR). The point where they are equal is the equal error rate (EER). The curve showing every possible trade‑off is called the DET (or ROC) curve.

Machine learning and neural networks

Besides distances, almost every machine learning technique has been tried: nearest neighbours (k‑NN), one‑class support vector machines, random forests and neural networks. One‑class methods are useful because in practice there are almost never impostor samples to train with.

The big leap came with deep learning and massive datasets. In 2018 a team at Aalto University published a study of 136 million keystrokes from about 168,000 volunteers. With data like that, researchers at the Autonomous University of Madrid trained TypeNet, a recurrent network that turns any snippet of free text into a vector and compares vectors with each other, making it possible to recognise people the network never saw during training and to scale to hundreds of thousands of users.

The trade‑off is that these models need a lot of data to train and are harder to explain. For a local program with a handful of people, well‑calibrated classic methods are still very competitive.

How to evaluate an algorithm properly

  • Use different sessions. Comparing samples typed in the same session gives overly optimistic results: the person was in the same conditions.
  • Keep enrolment and testing separate. Never test with the samples used to build the profile.
  • Include impostors who try to imitate. A random stranger is not the same as someone trying to copy your rhythm.
  • Report both error rates, not just accuracy: a system that rejects everyone has 0% false acceptances.

How KeyBio does it

KeyBio combines several of these ideas:

  1. The R and A measures on digraphs, trigraphs, hold times and flight times, between the new sample and each sample in the profile.
  2. The scaled Manhattan distance on global features: speed, pauses, use of capitals, corrections.
  3. A per‑user threshold with leave‑one‑out validation (leaving out whole sessions when there are several) and an adjustable sensitivity that can calibrate itself with the data on the computer.
  4. A progressive decision: from 60 keystrokes on it can answer early if the result is already clear.
  5. Spoofing detection that rejects robotic rhythms, exactly repeated timings and replays of stored samples.
